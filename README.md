# Tekhnopolis 🍽️

    Tekhnopolis - это онлайн платформа-торговой сети электроники

## Описание
    **Tekhnopolis** — тот проект представляет собой веб-приложение, предназначенное для управления иерархической сетью поставщиков электроники и связанными с ней данными. Он включает в себя систему аутентификации и авторизации пользователей, веб-интерфейс для просмотра данных, API-интерфейс и административную панель.

## ✨ Основные функции
    Основные функции:
    1. Система аутентификации и авторизации пользователей (users)
    Регистрация пользователей:
        Новые пользователи могут зарегистрироваться, указав имя, фамилию, email, телефон, город, фото (опционально), Telegram ID (опционально).
        При регистрации пользователь создаётся с is_active=False (деактивирован).
        Отправляется письмо на указанный email с уникальной ссылкой для подтверждения адреса. Письмо генерируется из шаблона email_confirmation.html.
        После подтверждения email пользователь становится активным и может войти в систему.
    Вход в систему:
        Аутентификация производится по email и паролю.
        Страница входа (/users/login/) имеет красивый дизайн с логотипом и ссылкой на восстановление пароля.
        Использует кастомную модель User (из приложения users), где USERNAME_FIELD переопределено на email.
    Выход из системы:
        Пользователь может выйти, нажав на кнопку "Выйти" в навигационной панели.
        Выход реализован через JavaScript, который отправляет POST-запрос на /users/logout/.
        После выхода пользователь перенаправляется на главную страницу (/), которая в свою очередь перенаправляет на страницу входа.
    Восстановление пароля:
        Пользователь может запросить сброс пароля, указав свой email.
        На указанный email отправляется письмо со ссылкой для сброса пароля (используется шаблон password_reset_email.html).
        По ссылке пользователь попадает на страницу ввода нового пароля.
        Страницы восстановления (/users/password-reset/, /users/reset/.../, и т.д.) имеют стиль, схожий с страницей входа.
    Профиль пользователя:
        Авторизованный пользователь может просматривать свой профиль (/users/profile/), где отображаются личные данные и (опционально) история бронирований.
        Пользователь может редактировать свои данные в профиле (/users/profile_edit/).
        Управление пользователями (для суперпользователей):
        Суперпользователь может просматривать список всех пользователей (/users/users_list/).
        Суперпользователь может переключать статус is_active (активировать/деактивировать) других пользователей через кнопку "Активировать/Деактивировать".
        Суперпользователь может удалять других пользователей через кнопку "Удалить".
        Если пользователь удаляет сам себя, он разлогинивается и перенаправляется на страницу входа.
    Администрирование пользователей:
    Встроенный интерфейс Django Admin (/admin/) позволяет суперпользователям управлять пользователями: создавать, редактировать, активировать/деактивировать, удалять, просматривать все поля модели User.
    
    2. Модель данных сети поставщиков (store)
    Иерархическая структура поставщиков:
       Сеть состоит из трёх типов участников: Завод-изготовитель, Розничная сеть, Индивидуальный предприниматель.
       Уровень иерархии определяется связью supplier (поставщик). Максимальная глубина — 2 уровня ниже завода.
       У каждого поставщика есть поля: название, контакты (email, страна, город, улица, номер дома), тип, ссылка на поставщика (не обязательна, но если указана, должна соответствовать бизнес-правилам), задолженность перед поставщиком, время создания.
    
       Реализована валидация на уровне модели, чтобы соблюдалась иерархия (например, завод не может иметь поставщика).
       Продукты:
       Каждый Product связан с конкретным Supplier.
       У продукта есть: название, модель, дата выхода на рынок.
    3. Веб-интерфейс (store)
    Главная страница (/): Показывает приветственное сообщение. Если пользователь авторизован, отображает его имя и ссылки на основные разделы.
       Если не авторизован, предлагает войти в систему.
       Список поставщиков (/store/suppliers/): Доступен только авторизованным пользователям.
       Отображает таблицу всех поставщиков с основной информацией.
       Список продуктов (/store/products/): Доступен только авторизованным пользователям. Отображает таблицу всех продуктов с основной информацией.
    Навигация:
       Правая верхняя навигационная панель отображается, если пользователь авторизован.
       Содержит ссылки: "Поставщики", "Продукты", "Профиль", "Выйти".
       Для суперпользователей добавляется ссылка "Пользователи".
    4. API-интерфейс (store, DRF)
          CRUD для поставщиков:
          Реализован ViewSet (SupplierViewSet) с полным набором операций: создание, чтение, обновление, удаление (/store/api/suppliers/).
          Поле debt (задолженность) запрещено обновлять через API (исключено из сериализатора SupplierCreateUpdateSerializer при create/update).
          Доступ к API защищён: только аутентифицированные пользователи могут выполнять запросы.
          Доступна фильтрация объектов по country (через filterset_fields).
          Доступен поиск по city (через search_fields).
      Схема API: оступна интерактивная документация API по адресу /api/docs/ (Swagger UI), сгенерированная с помощью drf-spectacular.
    5. Административная панель (store, Django Admin)
    Управление поставщиками:
       В /admin/ можно просматривать, создавать, редактировать и удалять объекты Supplier. В списке отображаются ключевые поля, включая уровень иерархии (get_level), ссылку на поставщика (supplier_link), фильтры по типу, городу, стране. 
       Добавлено admin action "Очистить задолженность у выбранных поставщиков", которое позволяет массово обнулить поле debt.
    Управление продуктами:
       В /admin/ можно просматривать, создавать, редактировать и удалять объекты Product.
       В списке отображаются ключевые поля, фильтры по поставщику (город, страна).

## 🛠 Технологии

    - **Backend**: Python 3.9+, Django 4.x, Django REST Framework
    - **База данных**: PostgreSQL (рекомендуется; совместим с другими СУБД, поддерживаемыми Django)

## 🚀 Установка и запуск

    git clone git@github.com:Grigorii-Goncharov/Tekhnopolis.git
    cd Tekhnopolis
   
    Создайте и активируйте виртуальное окружение:
      python -m venv venv
      source venv/bin/activate    # Linux/macOS
      # или
      venv\Scripts\activate       # Windows

    Настройте переменные окружения (создайте файл .env на основе .env.example, если он есть):
      SECRET_KEY=your_SECRET_KEY
      DEBUG=your_DEBUG
      DB_NAME=your_db_name
      DB_USER=your_db_user_name
      DB_PASSWORD=your_PASSWORD
      DB_HOST=your_host
      DB_PORT=your_port

    Выполните миграции и создайте суперпользователя:

      python manage.py migrate
      python manage.py createsuperuser

    Запустите сервер:
      python manage.py runserver
